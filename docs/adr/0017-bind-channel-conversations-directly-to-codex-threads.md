# Bind Channel Conversations directly to Codex Threads

The Bridge will not recreate Hermes-style sessions or derive filesystem projects from channel routing keys. Each Profile has one Workspace, each Channel Conversation has a stable Conversation Key, and its current Thread Binding points directly to a Codex Thread; `/new` replaces that binding with a new native Thread while `/attach` selects an existing native Thread. For a group, `group_thread_scope: conversation` shares that binding across the group, while `group_thread_scope: participant` derives a separate binding for each Provider Identity in the group; `conversation` is the default. Approval correlation always retains the Provider Identity that initiated the actual Codex Turn. Codex owns all history and context lifecycle below the Thread boundary.
