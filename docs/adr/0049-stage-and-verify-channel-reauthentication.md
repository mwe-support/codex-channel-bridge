# Stage and verify Channel reauthentication

QQ credentials are provisioned only through System Administrator-controlled Secret References, while an authorized Profile Administrator may initiate WhatsApp pairing through authenticated host-local IPC and receive the expiring QR or pairing code only in the initiating interactive CLI. Baileys state is staged separately and replaces active authentication atomically only after a successful connection proves the same Provider Identity as the existing Channel Account; mismatch, timeout, interruption, or validation failure discards the staged state and preserves the last valid state, and a different identity requires a new Channel Account. Reauthentication restarts only the affected adapter, and logs, persistence, diagnostics, and body-free Audit Records never contain pairing material, secret values, Secret Reference values, or raw Provider Identities.
