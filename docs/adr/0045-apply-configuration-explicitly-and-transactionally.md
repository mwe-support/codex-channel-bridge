# Apply configuration explicitly and transactionally

The first release will not watch `config.yaml` for automatic reload: a System Administrator uses `bridge config check` and an explicitly confirmed `bridge config apply`, which rereads environment overrides, validates the complete candidate, and rejects it without changing the current Configuration Revision if any static error exists. The apply plan exposes a redacted diff, affected Profiles, and required drain/restart actions without revealing secret values. Once accepted, affected Profiles transition independently—Workspace, Codex home, Channel Account, and App Server environment changes require bounded Profile drain and restart—and a runtime failure makes only that Profile unavailable rather than rolling back or disrupting healthy siblings.
