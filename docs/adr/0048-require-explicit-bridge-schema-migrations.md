# Require explicit Bridge schema migrations

Bridge installation and upgrades remain operator-owned, and normal service startup will not execute irreversible migrations: a newer binary keeps the Supervisor live while marking affected Profiles `unavailable: migration_required`. A System Administrator must inspect `bridge migrate plan`, bounded-drain each target, reference a completed backup manifest, confirm that the prepared data was externally snapshotted, and explicitly apply the plan. Each Profile database migrates and verifies independently with Audit Records, so failure does not alter or stop siblings; migration touches only Bridge-owned state and provides no automatic down migration. Binary downgrade is allowed only when release metadata declares schema compatibility, otherwise rollback restores the pre-migration snapshot before running the old version.
