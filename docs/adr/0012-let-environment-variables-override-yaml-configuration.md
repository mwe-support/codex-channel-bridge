# Let environment variables override YAML configuration

Environment variables override matching `config.yaml` values across every deployment target, and invalid policy names, malformed allowlists, or incomplete overrides fail closed rather than falling back to `open`; changes apply only through explicit configuration apply or restart, never file watching. Secret References resolve `env:NAME` from the actual process environment before a Profile-local persistent `secrets.env`, with `file:/absolute/path` retained for owner-only single-value files such as Docker Secrets. The Bridge never searches a Workspace or current directory for dotenv files, executes dotenv content, or stores secrets in `config.yaml`; `secrets.env` is atomically updated plaintext protected by strict ownership or ACLs, included as sensitive backup material, and excluded from logs, audits, support bundles, and Channel output. Platform credential stores or application encryption require a future ADR because the first release does not claim protection beyond its filesystem and OS-user trust boundary.
