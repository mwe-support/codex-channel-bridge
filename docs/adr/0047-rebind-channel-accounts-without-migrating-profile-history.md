# Rebind Channel Accounts without migrating Profile history

The first release permits a System Administrator to reassign an exclusively owned Channel Account only after the source Profile is disabled with no active Turn, pending Approval Request, or pending outbox delivery. Reassignment creates a new Channel Account Epoch at a recorded cutover boundary, and the target processes only post-cutover provider events so replayed events from the old epoch cannot start Codex work. It transfers no Message Archive, media, Access Policy, Conversation or Thread Binding, Codex history, credential, or Baileys authentication state; the target supplies new Secret References and WhatsApp pairs again. Both Profiles receive body-free Audit Records, the source keeps its historical epoch without send/receive authority, and a failed cutover leaves the account unbound rather than silently rolling it back; full history-and-credential migration requires a future ADR and security review.
