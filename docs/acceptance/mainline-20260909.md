## Remaining gates and prepared next step

- Same-provider WhatsApp private/group interruption still needs the user's
  decision on allowing the single test participant's private chat.
- QQ expiry, provider rate-limit/ambiguity and process-loss boundaries retain
  their existing acceptance requirements; deterministic tests are not labelled
  as new live provider faults.
- Linux/Docker real attachment upload, arrival and recipient-download digest
  checks require native login and fresh target credentials. A new owner-only
  Linux Profile is prepared with its QQ account disabled and policies denied.
  Its native credential storage was set to `file` through App Server
  `config/batchWrite` and read back. No existing Profile authentication was copied.
  The intended test uses that one Profile sequentially in native Linux and Docker
  with the same absolute data, Codex home and Workspace paths and compatible UID.
- The prepared interactive entry uses native `codex login --device-auth` and
  existing no-echo `bridge secret set`. Authentication and Channel activation
  are not yet complete. See [official authentication guidance](https://learn.chatgpt.com/docs/auth).
- Release and rollback gates remain separate. No requirement is promoted to
  universally done merely because this batch passed.
