Native Linux completed an authenticated Codex Turn and transported its native

`7d89e074dc54482a932673a507f81591a8e7ece695d139b029eab56f4b7f6752`.

process using the Profile Workspace before Docker started.

Docker mounts the same Profile at the same absolute data, Codex home and
Workspace paths with UID 1000. Only the configured Codex executable path changes
through the supported environment override. The container reported healthy,
Supervisor/Profile/adapter ready and resumed the same native Thread with its
Bridge binding unchanged. The original Slim image had no system CA bundle.
Two authenticated Turns made no progress toward file creation and were explicitly
interrupted after 310,104 ms and 196,459 ms. Both interruption results reached QQ;
the old container then drained and stopped with exit code zero.

The image fix copies the build stage's system CA bundle into the Slim runtime
and checks that it is nonempty during the build. Codex's
[upstream native TLS implementation](https://github.com/openai/codex/blob/0d46c252b3f29f10bacf0ef58a17a1aa5d17ead3/codex-rs/http-client/src/custom_ca.rs#L250)
loads platform roots for its WebSocket connector. The original native TLS error
text was not retained; the diagnosis is supported by the missing bundle, upstream
code and controlled image comparison. TLS verification was never disabled.

The repaired image is
`sha256:5a23c2c3b12bba0c3b1e0863e87519afa0392b73cc835b6323276e3093729623`.
Both images have identical compiled Bridge artifacts and the same native Codex
binary SHA-256 (`56ef98ab4032d317ab26e9b5e5a175650717351edb16ed9cde0cb6d1734d62da`).
The root-bundle check fails in the original image and passes in the repaired
image. An HTTPS probe explicitly using the system bundle completed verified TLS;
its unauthenticated HTTP 401 is not a model-authentication claim.

The repaired image completed the real authenticated Turn, including native

## Remaining gates

- Same-provider WhatsApp private/group interruption still needs the user's
  decision on allowing the single test participant's private chat.
- QQ expiry, provider rate-limit/ambiguity and process-loss boundaries retain
  their existing acceptance requirements; deterministic tests are not labelled
  as new live provider faults.
- Linux/Docker WhatsApp requires separate target-host pairing, and group-file
  scenarios remain open. The private QQ evidence above must not be generalized
  to every provider or conversation type.
- Release and rollback gates remain separate. No requirement is promoted to
  universally done merely because this batch passed.
