## Native contract and checks

The existing `readThreadSettings` uses `thread/resume` with only `threadId`.
The installed generated `ThreadResumeResponse` supplies `model` and nullable
`reasoningEffort`; the upstream response is built from a Thread configuration
snapshot. No setting overrides, config writes, model catalog defaults, or model
Turn are used for queries. Unloaded Threads may be loaded by native resume.
See the [official App Server documentation](https://developers.openai.com/codex/app-server).

The group and private routes have two distinct persisted Codex Thread IDs.
Successful query records have no Codex input correlation: they did not start
model Turns. The initial pre-fix group answer generated by the model is excluded
from query acceptance. Supervisor and both QQ/WhatsApp adapters are ready;
Dashboard was preserved across bounded restarts, with no schema migration.

This verifies two QQ conversations in one Profile, not every provider/platform
combination. Settings belong to native Threads: intentionally attaching multiple
conversations to the same Thread shares that Thread's settings. No new WhatsApp,
