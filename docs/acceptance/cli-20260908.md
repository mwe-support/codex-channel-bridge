## Regression checks and implementation corrections

- Configuration tests reject invalid targets, invalid/stale edits, incorrect
  confirmations, reserved keys and secret values passed as CLI arguments.
- Native model tests verify scope, discovery, optional capabilities, user-layer
  concurrency versions and output redaction. Queries do not resume Threads.
- QQ lifecycle tests preserve sibling adapters and Codex, reject pending delivery,
  and reject work arriving during quiescence checks or after disconnection while
  retaining its archive record. No outage backlog is created.
- Actual PTYs exposed and verified the correction for duplicate readline listeners
  echoing setup secrets. Linux prompt parsing now handles ANSI cursor sequences.
- Service acceptance exposed the need for an explicit Node PATH for Codex's
  launcher and for waiting for Supervisor exit after native service deregistration.
- Windows startup waits for its parent to attach the Job Object before permitting
  Profile children to start. A stopped parent cannot initiate work.
- systemd argument and environment handling preserve their distinct `$` rules.

## Latest live QQ boundary

On 2026-09-08 the candidate was loaded in the existing macOS test deployment.
A real QQ input was admitted; CLI disconnection during its active work correctly
failed with `channel_account_busy`. The native Turn failed and its failure status
was delivered to QQ. Native inspection classified authentication/authorization
as the cause; the selected Codex home reported `Not logged in`.

The user authorized reusing the host's existing Keychain login and completed
system authorization. Only the exact home-scoped Codex credential entry was read,
and the test Profile's owner-only native auth file was provisioned without printing
credentials or rewriting the source credential value. Native login status then passed. After
reloading the test Supervisor, a fresh real QQ input received its exact expected
positive reply. No Thread binding was changed by this final test.

QQ disconnect/reconnect also passed after the failed Turn. At the CLI checkpoint,
the WhatsApp sibling was degraded and its active authentication could not load;
QQ continued independently. Follow-up inspection established that the active
generation reference was missing while the original credentials remained present.
User-authorized reference recovery restored the original account without pairing
again. Subsequent persistent-storage migration and fresh QQ / WhatsApp round
trips are recorded in the [P0 / P1 execution record](p0-p1-20260908.md).
